처음에는 제목과 선별이 실패 단계였다. 후속 수정은 새로 선정된 원문에서 실제 관측·설계·편집 오류가 확인된 경우에 한했다. 추출 v6~v11을 일괄 적용하면 인용문의 월을 회의 시점으로 오인하거나 불필요한 날짜 때문에 유효 관측이 탈락하는 회귀가 있어 채택하지 않았다. 현재는 의사록 도입부에만 시점 지침을 적용하며, 계약통화라는 표현이 있는 기사에만 통화 비교 지표의 범위 보존 지침을 추가한다. 도입부 뒤에서 의사록임이 드러나는 기사는 이 추가 지침을 받지 못할 수 있다.

스프레드 교정은 해당 질문이 있는 묶음에만 적용한다. 일괄 편집 프롬프트 변경은 관련 없는 재정 소제목의 회귀를 일으켰으므로 적용 범위를 좁혔다. 질문 줄에 ‘스프레드’ 또는 ‘금리 차’가 없는 표현은 이 상세 지침을 받지 못할 수 있다. 일반 비교 보존 규칙은 모든 편집에 유지한다.

M2는 M1을 포함한다. 내부 예금 이동만으로 전체 통화량 증가를 설명한 오류는 설계 connection에서 처음 확인했다. 포함관계는 [한국은행 통화지표 정의](https://snapshot.bok.or.kr/dashboard/A5)와 해당 원문으로 확인했다. 이 정의 확인은 과거 사건 입력을 새 웹 자료로 보충한 것이 아니다.

새 분석 엔진·검증 LLM·자동 재작성 호출은 추가하지 않았다. 일일 USD 0.14, 모델, 추출·설계·편집 토큰 한도, 실제 수치·날짜·출처 검증을 유지했다. ‘제3국’ 종결형 수정은 수량 3의 면제가 아니며 3%·3개월·3개국 및 잘못 이어 붙인 표현의 거부 테스트를 유지했다.

- M1은 M2의 일부라는 포함관계, M2 내부 예금 이동과 총량 증가의 구분을 확인했다. 구체적인 신규 통화 창출 원인을 원문 없이 단정하지 않았다.
- MOU·항로별 운임 나열·품목 지원·개별 기업 실적의 독립 주제를 제거했다. 정유 공급 병목은 국제 연료 공급·물가 전파, 성장률 기사 속 반도체는 국가 성장 구성과 집중 위험의 근거로 사용했다. 분야명 일괄 차단이나 별도 업종 전망으로 평가하지 않았다.
- 15일 지역 가격 차이만 나열한 후보를 거시 주제로 승격한 문제는 선별에서 해결했다. 최종 주택 기사는 금리·대출 규제·정책 불확실성이 거래에 미치는 원문 근거를 가진 다른 기사다.

수정 후에도 7개 기준본 밖의 모든 중요 거시 근거를 포괄했는지, 선택 우선순위가 최선인지 확정할 수 없다. 기존 금융 제재 기사의 제외와 3일 표본의 제한은 남는다. 기계 검증 SUCCESS를 의미 품질 전체 PASS로 치환하지 않는다.

최종 63의 제목·본문·질문·답변을 기존 실제 응답과 비교했다. 14·15일은 검토한 59와 모든 흐름의 글이 일치하고, 16일은 앞 4개 흐름이 59, 나머지 6개가 61과 일치한다. 스프레드가 없는 묶음의 요청은 바뀌지 않았으며, 결과 문장을 수동으로 조립하거나 수정한 것이 아니다. 최종 제품 코드가 요청 조건에 따라 실제 파이프라인을 실행하고 동일 요청의 원래 응답과 usage를 복원한 결과다. `63-prose-provenance-check.json`, `63-code-manifest.json`에 일치 검사를 보존했다.


## 코드 검증과 재현

최종 `gradlew.bat clean build --console=plain`은 성공했다. 유료 재실행의 init 파일은 빌드 출력 경로만 분리한다. **68개 중 62개 실행·실패 0**, 유료 opt-in 6개는 일반 빌드에서 skip됐다. 버전 표식의 DB 길이 계약을 검사하며, 같은 기사의 다른 관측에 있는 연도도 질문의 허용 숫자에 들어오지 않으며 실제로 쓰면 여전히 실패하는 것을 확인한다. 로그는 `pipeline-debug/macro-selection/62-clean-build.log`, 요약은 `62-offline-test-summary.json/html`에 보존했다. 유료 opt-in 테스트의 일반 빌드 skip을 전체 실행 통과로 세지 않는다. 원본 결과는 `pipeline-debug/macro-selection/63-scoped-validation/`, 로그는 같은 이름의 `.log`, 기계 판독 요약은 `final-audit.json`이다. 날짜별 `*-reading.md`는 결과를 읽기 쉽게 풀어 쓴 검토용 복사본이며 공개 결과를 변경하지 않는다.

재현은 frozen corpus를 새 `economic_briefing_review_macro_*` DB로 복원하고 `MACRO_PIPELINE_DB`, `MACRO_PIPELINE_ROOT`, 새 `MACRO_PIPELINE_ATTEMPT`를 설정한 뒤 `gradlew.bat test --tests '*MacroPipelineReplayTest.replay'`를 실행한다. `PGUSER`, `PGPASSWORD`, `OPENAI_API_KEY`는 비밀 환경변수로 전달한다. 검증 DB에는 vector extension이 필요하다. 같은 실험 디렉터리는 덮어쓰지 않는다.

## 남은 한계

- 당시 전체 후보·본문 판본이 없으므로 완전히 동일한 운영 입력의 품질·비용 회귀는 확인할 수 없다. 다른 로컬 작업 폴더도 확인했지만 16일의 전체 원본을 찾지 못했다.
- 기존 금융 제재 기사(150057)는 유효한 거시 근거일 수 있으나 최종 선택에서 제외됐다. 부분 기준본 7개 충족만으로 이 우선순위의 최적성이나 전체 중요 뉴스 포괄성을 증명하지 않는다.
- 프롬프트의 작은 변경에도 선택이 달라지는 사례가 있었다. 동일 요청 캐시를 재사용한 검증은 확률적 안정성의 반복 표본 실험이 아니다.
- 의사록 도입부 감지와 관계 단어 기반 원문 발췌는 제한된 휴리스틱이다. 모든 필요한 문단이나 기사 유형을 포괄한다고 보장하지 않는다.
- 운영 환경의 추가 본문 HTTP 조회 지연은 측정하지 않았다. 전체 실행은 고정 본문을 주입한 격리 DB 검증이다.

크레딧 부족을 해결 불가 사유로 남기지 않았다. 확보한 자료에서 수정·재실행을 수행한 범위와 과거 입력 부재·잔여 판단 한계를 구분하며, 전체 품질 PASS나 배포 완료로 보고하지 않는다.
