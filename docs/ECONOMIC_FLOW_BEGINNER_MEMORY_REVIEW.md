## 2. 기억 선정 평가 — 사용자 판단 대기

사용자가 기사별로 남길 정보와 버릴 정보를 아직 정하지 않았다. 첫 모델 출력은 아래 실행 기록에 보존했다. 이 표는 이후 사용자 판단을 기록할 양식이다.

매번 함께 보여줄 것:

1. 기사 제목·발행시각·확보한 원문과 문단 번호
2. 모델이 기억으로 선택한 정보

선택된 정보만 검사하지 않는다. 사용자가 원문에서 추가로 지목한 사실·이유·조건을 누락 사례로 기록한다. 실험 후보는 운영 과거 기억 DB에 자동 반영하지 않는다.

### 재현 확인과 다음 단계

`treasury_cache_check`에서 같은 원문·DB 복사본과 동일 요청 캐시를 재사용했다. 질문·편집 출력이 일치했고 새 호출 비용은 USD 0이었다. SQL 재사용 시 원문 변경 감지와 근거 없는 기억의 DB 제약도 통과했다. 새로운 기사 시험이나 프롬프트 품질 튜닝은 아직 하지 않았다.

**새 독자 기준:** 사실을 읽는 능력과 경제적 관계를 이해하는 능력은 다르다. 매매 동기·가격 형성·지표의 역관계도 전제로 두지 않는다. 한 문장에 있는 연결마다 독자가 막힐 수 있다. 질문 개수를 다섯 개로 고정하는 규칙은 아니다.

### 단계별 확인과 수정

1. 질문 선정 모델은 압축 관측만 받아 원문의 ‘매도가 이어졌다’를 보지 못했다. 이미 관측에 연결된 원문 근거 문단을 중복 제거해 planner에도 전달했다. 전체 기사 원문을 추가로 전송하는 방식은 아니다. 기존 15,000 token 입력 상한을 유지한다.
2. 처음에는 지침만 추가해도 넓은 왜 질문 안에 여러 단계를 묶었다. 이해가 막히는 개별 연결을 질문으로 만들도록 소득→소비→생산→고용이라는 다른 주제의 짧은 예시를 추가했다. 예상의 근거와 기대 미달에 따른 행동 동기는 서로 대체하지 않는 의문으로 명시했다. 사용자 질문 다섯 개를 입력에 그대로 넣거나 고정 결과로 반환하지 않는다.
3. 현재 기사에 있는 기대 형성 발언(P008)이 제목·요약 AND 검색을 통과하지 못했다. 질문이 연결된 현재 기사를 먼저 확인하게 했다. 2,000자 이하의 짧은 기사에서는 근거 가능한 문단을 온전히 확인하고, 긴 기사는 기존 여섯 문단 제한을 유지한다. 전체 8기사·8,000자 상한, 원문 중복 제거와 시점 검증은 유지한다.
4. 설계에서 사용하지 않은 경제원리가 질문 검색의 네 청크 예산을 차지했다. 실제 선택한 원리만 예약하게 하고 검색 원리 후보를 trace에 남겼다. 관련 없는 원리를 억지로 사용하지 않는 것은 편집 지침에서 확인한다.
5. 편집기의 ‘짧은 설명’ 설정이 새 독자 기준과 맞지 않아 답변 상세도를 medium으로 변경했다. 기대 미달·매도세·역관계라는 말로 설명을 끝내지 않고 무엇이 그대로이고 무엇이 달라지는지 풀도록 했다. 다른 주체·수단의 경제원리를 이번 정책으로 옮기지 않는 경계를 추가했다.

한 번의 수정으로 모든 질문을 충족했다고 처리하지 않는다. 각 실행의 원출력·usage·FAILED 원인은 보존한다. 의미 품질은 사용자 재평가 전이며, 추가 질문이나 기억의 사용자 판단은 추정하지 않는다.

## 6. 사용자 피드백 2 — Q03 설명 깊이 수용

사용자 원문: “Q03 괜찮아! 이정도 딱 좋아. 이해할 수 있어. 아직 어렵긴한데 다음에도 비슷한 기사나왔을 때 계속 설명해주면 이해할 수 있을 듯”

## 15. 드라기 기사 피드백 — 제안이 필요한 이유를 함께 기억

사용자는 이 기사를 고른 목적이 데이터센터 구축 주장의 구체적인 이유를 기억하는지 확인하는 것이었다고 설명했다. 필요한 근거는 P012의 두 경로다: 유럽 기업이 데이터를 역내에 유지하지 못해 AI 도입을 포기할 수 있고, 연산 비용 상승으로 저부가가치 산업의 AI 도입이 둔화할 수 있다는 드라기의 우려다. 후속 유럽 데이터센터 기사에서 ‘왜 유럽은 데이터센터에 이렇게 집착하는가’에 답할 근거로 보존해야 한다. 사용자 원문은 `draghi_ai_002_selected/feedback.json`에 기록했다.

- 이는 선택적인 설명 누락이 아니라 사용자 지정 **필수 기억 근거**다. 앞선 에너지 안보 설명의 ‘있으면 좋음’ 판단을 이 사례에 적용하지 않는다. 기존 M02·M03 삭제나 Q01~Q04에 대한 새 판단은 추정하지 않는다.
- 원문 P012는 001·002의 실제 추출 요청에 모두 있었다. 001의 M03에는 관련 우려를 담았지만, 사용자에게 제시한 002는 제안·지표·투자 지연 요인으로 세 항목을 채우면서 P012를 누락했다. 원문 미수집이나 검색 실패가 아니라 최초 추출·기억 선정의 일관성 문제다.
- 추출 지침은 핵심 변화의 원인이 제목·리드에 있을 때 결합하도록 강조했지만, 제안의 필요성을 말미의 조건부 우려에서 찾아 보존하는 우선순위는 약했다. ‘왜 필요한가’가 ‘왜 지연되는가’와 같은 나머지 후보로 경쟁했다.
- 수정은 관측 추출 지침에 한정한다. 제안과 원문이 밝힌 핵심 이유를 같은 `text`에 연결하고 이유 문단을 `spanIds`에 포함하도록 했다. 추출 버전을 `observation-memory-v3`로 올려 기존 v2 관측을 새 기준의 결과로 재사용하지 않는다. 0~3개·220자, 검증, 모델·schema·일일 비용 가드는 그대로다. 선별·질문 선정·검색·편집 지침은 바꾸지 않았다.
